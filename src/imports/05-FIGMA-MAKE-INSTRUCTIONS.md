# Feul --- Figma Make Build Instructions

## Objective

Use the supplied Feul product context plus the user's attached visual
references to build a coherent, production-plausible mobile product.

Do not treat the references as screenshots to reproduce.

Extract their useful principles and create a new system for Feul.

## Build order

### Phase 1 --- Foundation

Create:

-   color variables
-   typography variables
-   spacing variables
-   radius variables
-   elevation
-   semantic states
-   Material 3 components

### Phase 2 --- Feul identity

Add:

-   electric violet/periwinkle accent
-   restrained gradient system
-   acoustic waveform language
-   typography hierarchy
-   task visual language
-   earning/progress language

### Phase 3 --- Core components

Build:

-   top app bar
-   avatar
-   notification
-   three-item bottom navigation
-   task tabs
-   task row
-   task card
-   earnings module
-   coverage badge
-   language metadata
-   audio player
-   waveform
-   primary CTA
-   status components

### Phase 4 --- Core screens

Build in this order:

1.  Home
2.  Jobs
3.  Job Detail
4.  Studio
5.  Wallet
6.  Profile

Then add onboarding and edge states.

## Visual constraints

Use: - cool neutral background - crisp black typography - white
surfaces - restrained violet/periwinkle accent - gradient only where it
communicates voice/audio - subtle shadows - clean spacing - strong
alignment - minimal chrome

Do not use: - terracotta - warm beige - clay - 3D illustrations -
excessive glass - neon - random blobs - excessive pills - generic AI
assistant graphics - giant decorative hero illustrations - card grids
with no information purpose

## Interaction principles

The product should feel interactive without becoming gimmicky.

Good: - expandable earnings module - horizontal opportunity browsing -
selected task tabs - waveform playback - resume active session - clear
progress - bottom navigation state - contextual CTA changes

Avoid: - unnecessary carousels - hidden gestures - decorative
animations - interactions that are impossible to implement

## Home-specific instruction

Do NOT build a generic dashboard.

The Home screen answers:

**What can I do right now, and how much will I earn?**

The primary content should be:

1.  personal state
2.  earnings/progress
3.  current task state
4.  next job
5.  more work

Do not fill space with generic feature marketing.

## Audio identity

The waveform must recur across the system.

Examples:

Home: - subtle earnings/audio progress visualization

Jobs: - tiny audio indicator only where relevant

Job detail: - sample waveform

Studio: - full live waveform

Review: - clip waveform

Wallet: - no waveform unless it communicates a real relationship

## Content rules

Use realistic Indian-language examples.

Examples: - Hindi - Marathi - Tamil - Bengali - English

Use rupee values.

Example task: **Local shop conversation**

Example: - Hindi - Scenario - \~6 min - ₹42 - 1.6× coverage

Do not make the app feel geographically personalized unless the job
actually requires location.

## Quality bar

Before finalizing each screen ask:

1.  Does every element have a product reason?
2.  Is the hierarchy obvious in three seconds?
3.  Is the screen buildable?
4.  Does it feel like the same product as every other screen?
5.  Is the waveform doing meaningful work?
6.  Is the visual identity recognizable without the logo?
7.  Is there unnecessary UI?
8.  Does this feel like a 2026 product rather than an AI-generated
    dashboard?

## Reference handling

The user may supply additional screenshots/reference images.

When references conflict:

1.  Product requirements win.
2.  UX architecture wins.
3.  Design-system rules win.
4.  Reference visual treatment is inspiration only.

Do not blindly combine all references.

Find the shared design principles and synthesize them into one coherent
system.

## Final instruction

Build Feul as a **premium, crisp, acoustic-first contributor
marketplace**.

It should feel: - calm in browsing - expressive in audio interaction -
clear around money - trustworthy around consent - distinctive through
waveform language - structurally grounded in Material 3 - visually
original rather than a clone of any reference.
